0009-judgment-layer

改了什么

确定性检测器只能报”一跳”发现，make eval 里 5 条深发现全漏。本 change 加了判断层：每条线索先由代码取证并算好候选数字，再交给 LLM 单独判断；LLM 只能选候选，不做算术。判断经过严格校验后变成发现，走和确定性发现一样的不变量。

  • finops_agent/judge/：取证器（NAT 涨价、无 ID 数据传输、fleet 有效工作、空闲时段）、prompt、校验器、并发调用。
  • finops_agent/llm.py：record / replay / live 客户端，cassette 键 sha256(model + prompt)，默认 replay。
  • 新线索生成器：按小时 CPU 找出只忙一部分时间的非 ASG 实例（dev、夜间 ETL、DR 温备）。
  • 报告：线索卡片显示判断与理由；新增「Agent 成本」。

判断层的 5 条发现：NAT 路径（M6，$2,332.80）、跨 AZ（M6，$759.85）、ingest fleet 忙但无用（M3，$1,468.80）、夜间 ETL 常开（M6，$224.40）、dev 调度（M4，$0.00，被 Savings Plan 吸收）。web fleet 和 DR 温备被判为不是浪费。

约束是怎么落实的

  • FA03 数字来自代码：节省金额取自模型选中的候选，文字里的数字必须出现在证据里（1% 容差）。
  • FA11 上下文隔离：每条线索一次调用，prompt 只含这条线索的证据；测试用真实数据重建 prompt，与 cassette 逐字比对。
  • FA01 证据：模型必须引用证据编号，校验器核对编号存在。
  • 不可信输入：tag 与 Name 只出现在 <untrusted_metadata> 块里；带注入文本的实例照样被标出。
  • FA07 确定性的闸：带 dr / keep 等意图 tag 的资源被判浪费，代码直接拒绝。

成本与可复现

replay 模式从 eval/cassettes/（7 个文件）读取，不需要网络和 API key，CI 里显式 FINOPS_LLM_MODE=replay。7 次调用：23,349 输入 tokens，4,926 输出 tokens，$0.1426，单次延迟 4.2 到 10.2 秒（录制值）。

局限

  • prompt 的 rubric 是对着这个账号迭代出来的（6 轮全量录制），数字不能当作泛化能力的证据；要换账号验证需要 c0010 的”下个月”场景。
  • 重录会改变判断。一次重录里 NAT 线索变成”证据不足”，靠补一条算出来的事实修复。cassette 是一次采样。
  • 取证器按线索种类写死，新增种类要新增取证器。
  • 第一批录制的 usage 异常（cache_read 约 73K），原因没查清，已丢弃重录。
