0004-test-env 博客笔记

  • 好的 FinOps 测试数据，难点不在规模，在”浪费藏在哪”。只找闲置资源的检测器，在这个 $8.7K/月的账号里只能找到不到 $100。
  • 最深的一条：CPU 60% 看起来很健康，但成功 job 数从 09-04 起是 0。同一个根因（下游队列被删、重试 ×6）同时抬高了计算、NAT、S3 三行账单。
  • 最反直觉的一条：给 dev 环境做开关机，账面省 $580，实际约等于 0，因为那些小时由一个已经用不满的 Savings Plan 支付。承诺会改写节省。
  • 陷阱和发现一样重要：平均 27% / p95 76% 的潮汐车队、温备 DR、被在用 AMI 引用的快照、Name tag 里的 prompt 注入。eval 要同时考 recall 和”不乱报”。
  • 假服务要”像真的”才有价值：用 botocore 自己的 service model 序列化响应，boto3 和 aws CLI 不改一行就能用；以后换真账号只是去掉 endpoint_url。
  • 只读是两层：项目 hook 拦 CLI，服务器拒绝所有写操作。绕过 hook 用 boto3 直接写，依然被拒，和真实 IAM 只读角色一样。
  • 不支持的 PromQL 返回 bad_data，而不是猜一个结果。假服务也不能有”幻觉”。
  • 自洽测试：ground truth 里的节省区间由成本模型推导校验。测试数据自己也要有测试。
  • 踩坑：12 位数字的泄漏规则误报了资源 ID 后缀（vpc-0main000000000001）；测试夹具只复制部分文件，规则层一引用新文件就挂。
