这个项目是什么

一个带证据找云上浪费的 AWS FinOps agent，同时是一份用 spec、评估和护栏构建 LLM agent 的完整样例。只读，不需要真实 AWS 账号：合成账号和两个测试服务器就在仓库里。

第一部分 · FinOps

领域模型（单价 × 用量 × 时长，挂在资源、服务、团队上）和成本优化方法 M0 到 M6：先删、再降、最后买承诺；潮汐不是浪费；节省不超过花费。产物是带证据和口径的发现、SLO、腐烂检测和节省核实。

docs/METHOD.md · docs/FINOPS_SLO.md

第二部分 · agent 工程

怎么让一个 agent 可控、可度量、可改进：数字由代码算，LLM 只判断且被校验；元数据按不可信输入处理；三层只读；eval 基线只升不降；每个改动是一份 spec、按阶段的 commit 和带证据的验收。FinOps 是载体，这一部分才是重点。

README · CONTRIBUTING.md

10 分钟读法

  1. 2 分钟README：「我怎么思考这个 agent」那张表：每个设计决定对应一个问题和一个回答。
  2. 2 分钟本页的架构图和数据流图：先有全局：一条流水线，三层护栏，产物长什么样。
  3. 2 分钟最新 demo 报告：看一条发现从证据到处置计划是什么样子。
  4. 1 分钟METHOD：M0 到 M6：为什么先删再降最后买；为什么潮汐不是浪费。
  5. 1 分钟测试账号目录：标准答案和陷阱怎么设计，难度从哪来。
  6. 1 分钟节省核实：清理见效是账单上的数字，不是叙述。
  7. 1 分钟改动一览表：每个 change 的动机一句话，点进去看报告和笔记。
