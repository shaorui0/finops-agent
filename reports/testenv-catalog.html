发现

GT01

Ingest fleet burns full compute on jobs that all fail

M3 删除4 跳$1,300 至 $1,500 / 月证据 cost_explorer, ec2, metrics
  1. CE compute by service is normal
  2. CPU ~60% looks healthy
  3. ingest_jobs_total{status=succeeded} is flat since 09-04
  4. ingest_downstream_errors_total{reason=QueueDoesNotExist} explains it

现状 status

ingest-asg 共 6 台 c5.2xlarge，本月计算费 $1,469。CPU 均值约 59%，看着健康。但 ingest_jobs_total{status='succeeded'} 自 09-04 起不再增长，每个任务重试 6 次后失败，下游报 QueueDoesNotExist。

期望 spec

消费链路健康：成功任务数与尝试数同量级，useful_work_ratio ≥ 95%。队列存在，worker 才占用计算。

差异 diff

成功任务数为 0，$1,469 的计算费全部花在失败任务上；叠加 GT02 的 NAT 放大。可省 $1,300 至 $1,500。

处置 runbook

  1. 验证只读 查 sum by (status) (increase(ingest_jobs_total[1d]))，确认 succeeded 自 09-04 起持平。
  2. 验证只读 查 ingest_downstream_errors_total 的 reason 标签，确认是 QueueDoesNotExist。
  3. 验证只读 aws sqs list-queues 确认目标队列确实不存在，向 team-data 确认是被删还是改名。
  4. 处置由 team-data 恢复或改配队列。需要先止血时，由 owner 把 ingest-asg 期望容量调到 0 需人工审批 可回滚，agent 不执行。
  5. 确认队列恢复后 succeeded 恢复增长，告警 BusyButUselessFleet 清除，下次巡检该 finding 变 resolved。

预防 prevention

控制删除队列前必须先查消费者，写进变更评审清单；任务失败率进告警，不靠账单发现。

告警BusyButUselessFleet（page，持续 30 分钟），配合 RetryStorm。

节奏每日巡检看 useful_work_ratio（docs/FINOPS_SLO.md Cadence 每日）。

GT02

NAT processing cost multiplied by retries; S3 traffic should not use NAT at all

M6 架构3 跳$2,400 至 $2,900 / 月证据 cost_explorer, ec2, metrics
  1. CE usage type NatGateway-Bytes spiked after 09-04
  2. ingest retries x6 each re-download from S3
  3. no S3 gateway endpoint in the VPC

现状 status

NatGateway-Bytes 本月 $2,614，基线用量只值 $54.00。重试把每次 S3 下载放大 6 倍。VPC 内有 0 个 S3 gateway endpoint，S3 流量全部经 NAT。

期望 spec

S3 流量走 gateway endpoint（无处理费），NAT 只承载必须出公网的流量；NAT 字节量与业务量同比例，不随重试放大。

差异 diff

NAT 处理费 $2,614 对基线 $54.00，多出 $2,560。两层原因：重试放大（修 GT01 后消失），endpoint 缺失（独立存在，永久浪费）。可省 $2,400 至 $2,900。

处置 runbook

  1. 验证只读 Cost Explorer 按日看 usage type NatGateway-Bytes，确认 09-04 起跳涨。
  2. 验证只读 aws ec2 describe-vpc-endpoints 确认没有 S3 gateway endpoint；aws ec2 describe-route-tables 确认私有子网默认路由指向 NAT。
  3. 处置先按 GT01 停掉重试。再用 Terraform 新增 S3 gateway endpoint 并关联私有路由表 需人工审批 可回滚。
  4. 确认路由表出现 S3 前缀列表路由；次日 NatGateway-Bytes 回落，告警 NatBytesSurge 清除。

预防 prevention

控制VPC 模块默认创建 S3 gateway endpoint；自定义 AWS Config 规则检查每个带私有子网的 VPC 都有该 endpoint。

告警NatBytesSurge（NAT 字节超 7 天均值两倍持续 1 小时）。

节奏每日巡检看 anomaly_time_to_detect_days。

预防 prevention

告警FinOpsSLOViolated 覆盖 visibility_coverage（跨 AZ 归因缺口见页尾）。
