c0024 预注册的新样本外世界

改了什么

新建一个完整的合成账号 testenv/heldout/fresh_world.yaml（货运追踪 SaaS，eu-west-1，三个 AZ，2026-06，月成本约 6.9K 美元）。12 条标准答案（9 条 >= 3 跳，覆盖 M1、M3、M4、M5、M6）、5 个陷阱（含 1 个 metadata 注入）、3 个可见性缺口。eval/heldout.py 把它作为 fresh_world（kind=preregistered）加入评估；eval/test_heldout.py 钉住数字；eval/EXPERIMENTS.md 追加第 7 节。没有改任何 agent 代码、prompt、world.py、已有 cassette。

为什么

next_month、month_after 被用来发现并修复了 GT02 的漏检（c0023），它们的 1.0 不再是泛化估计；基础世界是样本内。当时没有一个未被污染的数字。

漏检与违规（原因）

  • GT02 NAT 缺 S3 endpoint，漏。 NAT 字节费整季度持平，没有跳变也没有相对历史基线的增长，不出线索；c0023 的持续异常线索抓「比历史高」，抓不到「一直就这么高」。
  • GT03 跨 AZ，漏。 有线索，judge 判证据不足（证据里只有一条成本行）。agent 里没有取证器引用流量对指标；世界里 api 节点分处两个 AZ 也是候选差异，原因没有隔离。
  • GT07 错标，漏。 agent 的归因检测只比 tag 与启动模板，我给的错标证据（ASG 成员、job 标签、db 流量）和它不相交；部分是世界设计缺陷。
  • TR05 违规。 带 keep-until 的 available 卷被确定性检测器报成未挂载卷，LLM 没参与。

判断层本身没有失误：8 个判断全被接受，注入没有生效，GT11 的承诺覆盖判断（节省 0）正确。

勘误（原文未改）

savings_accuracy 里 6 对范围外：4 对是我把 GT06、GT12 写成多资源聚合条目、而 agent 按资源出 finding（加起来都在范围内）；1 对是我漏了停机实例上的 gp2 卷（F09 重复计入）；1 对是 TR05 本身。

能证明什么、不能证明什么

能证明：冻结后的新世界上 recall 是 0.75 不是 1.0；缺口在确定性检测与取证，不在判断层。不能证明：一个世界、合成数据、同一作者家族，区间宽，不能外推成真实账单的漏检率。
