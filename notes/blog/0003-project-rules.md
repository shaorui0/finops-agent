# 0003-project-rules 博客笔记

- 蒸馏的关键是删：母版 50 条公理只带 11 条，私人信息一律不带。每条带进来的必须写出「本仓库怎么落地」，写不出来就说明它在这里只是口号。
- 公理要可执行：FA04「误差会级联」直接变成 eval 不变量 `savings ≤ spend`；FA06「控制回路」变成修复动作要标撤回成本。
- 两条公理是项目自己长出来的（以终为始、潮汐不是浪费），来自做这个项目时的语音。规则层不只从母版往下流，也可以反向提议回母版。
- 泄漏扫描的悖论：如果把雇主名写进扫描规则，规则本身就泄漏了。解法是公开模式进代码，私有模式进 gitignore 的本地文件。
- 测试也会泄漏：单测里写了一个 12 位数字当反例，自己的扫描器先把它抓了。改成运行时拼出来。
- 负向验证抓到了一个计划外的 bug：空目录不进 git，新 clone 缺 `openspec/specs/`。只跑正向验收是发现不了的。
- 规则层的验收不能靠人看，靠 `check_rules.py`：结构、引用、公理四段、索引互查、泄漏。以后 cron 直接复用它做回归。
