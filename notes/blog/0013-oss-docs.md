# 0013-oss-docs 博客笔记

- 产物字段清单不要凭读代码手写。先真跑一遍流水线，再用脚本把真实 JSON 的每个 key 去文档里找反引号，漏一个就补一个。这样文档和代码的漂移能被机器发现。
- 链接检查要给「生成物」留出口：`runs/` 被 gitignore，文档里必须提它，脚本就得显式列出被跳过的词，而不是悄悄放过。
- 贡献指南里写「基线只应上调」，但代码里没有任何东西强制它。写文档时会撞见这类「约定不是机制」的地方，要如实标成约定，别写成闸门。
- 并行开发的功能（判断层、处置方案）只写「进行中」，不写接口。先写出去的接口，会在另一个 change 合入时变成过期文档。
- 「不针对标准答案写死 ID」是开源后最容易被破坏的规则，所以放进硬规则，并且把检测器的陷阱处理写成「靠逻辑绕开，不靠名单」。
