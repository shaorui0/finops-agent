# 0000-init 博客笔记

- 面试只面一个东西：与其讲十个零散经历，不如一个项目同时证明领域模型（FinOps）和 Agent 工程能力。
- 定位是 Agent Engineer，不是 Agent 应用开发：卖点在 spec、eval、harness、context 这一层，不在"调了个 LLM"。
- 旧项目的教训：成本报告里 savings 比花费还大，说明没有对账就没有可信度。新项目把 "savings ≤ spend" 写成 eval 不变量。
- LLM 只做判断层，算数交给确定性代码：每个数字可复算，幻觉面就只剩解释和归类。
- 成本数据本身就是 prompt 注入面：tag 值、资源名都是任何人能写的字符串。
- 浪费分短期和长期：潮汐峰值是弹性在工作，长期不降才是浪费。
- 治理顺序：删 → 降配 → 承诺。先买承诺等于给浪费上锁。
- 过程即交付：每个 change 带验收证据、HTML 报告和这样一份笔记。
