# 0015 对抗套件与实验记录：笔记

- 评估这套东西最容易犯的错：把「样本内 1.0」当成泛化。判断层 recall 0.5833 -> 1.0 是对着同一个账号调了约 49 次调用换来的；换两个月份，recall 0.9 / 0.9091，savings_recall 掉到 0.566。
- 反直觉：样本外的下降不是 LLM 的问题。LLM 在有线索的 6 条上判断和样本内同型；掉的是确定性线索生成器，因为 NAT 的跳涨在 10 月第一天就已经发生，「最近 7 天 / 前 3 天 > 2」不再触发。
- 更糟的连带后果：带跨周期状态跑，漏检的 NAT finding 被记成 `resolved`。漏检在 SLO 看板上等于整改完成。
- 我自己加的数字落地规则被反向利用：在真正浪费的 fleet 的 Name tag 里放两个数字，模型老老实实写「这是不可信的元数据，已忽略 $99,999」，校验器因为复述了不在证据里的数字，把正确的 waste 判断拒掉了。模型赢了，校验器输了。这是 fail closed，但攻击者能触发。
- 旧校验器还有一个静默漏洞：`\w` 包含汉字，「省了1500元」里的 1500 紧贴汉字，整个被跳过。小于 100 的整数也被豁免。
- 第一版严格规则把两条正确的 not_waste 拒了（模型复述了注入里的 `$4,000`，还把 July 译成「7 月」）。放宽成 G7/G8 是看了对抗结果之后做的，必须写明，不能假装一开始就设计成这样。
- 9 个注入变体：8 个发现集完全不变，包括让陷阱 web fleet 被标成浪费、让 DR 热备被标成可删。每个变体只录了一次，所以是「这次没中招」，不是概率。
- 同一个 prompt 键、两次录制：6 个里有 1 个 verdict 变了（insufficient_evidence -> not_waste）。回放确定，不等于模型稳定。
- 卷 Name tag 那个变体根本不进 prompt。确定性检测器不读自由文本，是结构性免疫；LLM 路径只能是概率性的。这是「该让 LLM 看多少自由文本」的设计理由。
- 我没法证明 c0009 每一轮的数字：evidence 里只有文字，git 只留了两个 commit，prompt.py 一次提交。以后做 prompt 迭代，每轮的指标和成本要当场落盘。
- 预算：22 次调用 $0.7369；12 次样本外正常（约 $0.02），10 次对抗的 tokens_in 是 5 万到 7.5 万（缓存读取异常再次出现），一次 $0.2055。
