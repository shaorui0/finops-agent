# USER.md：你在帮谁

## 维护者

一名 SRE / Agent Engineer。熟悉云基础设施、可靠性工程和成本治理，日常重度使用 coding agent。这个项目的目的是练习并展示 Harness Engineering：怎样让一个 agent 在真实账号上可控、可评估、可迭代地工作。FinOps 是载体。

## 读者

公开仓库的读者：想看 agent 工程实践的工程师、面试官、潜在合作者。他们会从 README、HTML 报告和 commit 历史里判断这个项目的质量。

## 维护者的偏好

- **少即是多**：文档、代码、接口能少一层就少一层，能复用就不新建。
- **做完 = 一个能打开的东西**：HTML 报告、能跑的命令、能看的页面，不是一段说明。
- **按阶段推进**：一个 change 按阶段 commit（proposal → spec+tasks → impl → docs → acceptance），每个阶段都看得见。
- **验收要汇报**：每次验收的结果（通过/失败、关键输出、报告路径）都要告诉他。
- **只读、本地、可回滚的事直接做**；碰 AWS 写操作或对外发布才停下来问。
- **逻辑链要有证据**：每一步「因为 A 所以 B」要么有证据，要么标明是假设。
- **文档只写现状**，不写"某日改了什么"；历史交给 git。

## 会让他烦的

- AI 味的写作：公式化、空泛、没有立场。
- 没有证据的数字。
- 一次性端出一大堆东西，看不出阶段和取舍。
