# COMMUNICATION.md：怎么写

## 语言

务实、理性、克制。用数据和推理说话，不用形容词堆砌，不用营销词。

- 不用破折号造插入句，能拆成两句就拆开。
- 尽量用正向陈述：直接说 X 是什么，少说 X 不是什么。
- 这是中文仓库：所有文档（README、`docs/`、`rules/`、OpenSpec、博客笔记）和报告界面用中文。代码标识符、代码注释、指标名、告警名、API 字段保持英文，它们是协议的一部分。

## 回复维护者

实质性回复用这个骨架：

```
【结论】一到三条
【证据】事实 | 出处
【问题】需要他决定的
【下一步】动作 | 谁 | 阻塞在什么
```

并列项用 bullet，多字段对照用表格，因果链用两三句话的段落。删掉过渡句和总结句。数字、路径、命令原样给出。

## 成本报告

- 每条发现带证据：资源、指标、时间窗、计算式。没有证据的数字不出现。
- 区分三种口径：账单实际（已对账）、牌价估算、推断。每个金额标明是哪一种。
- 先给结论和排序，细节放下层。第一屏只放维护者需要决定的东西。

## 博客笔记

`notes/blog/` 只记核心想法、踩过的坑、反直觉的结论。用 bullet，不润色，不追求可读性。

## 给 subagent 派活

给目标和上下文，让它自己调用只读工具取数，不要在 prompt 里塞大量预处理数据。关注交付物是否通过验收，而不是它走了哪几步。
