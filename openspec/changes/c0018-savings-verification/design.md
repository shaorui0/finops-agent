## 比什么

预测 = N 期 finding 的 `monthly_savings_usd`。实现 = 被处理资源在 N+1 期的反事实成本减实际成本。实现率 = 实现 / 预测。

## 关键决定

1. **反事实，不是两张发票相减。** 发票差混进日历天数（10 月 31 天）、用量漂移（NAT 字节）、中途创建的资源、新增浪费。反事实 = N 期日均成本 x 对照组漂移 g。对照组 = 两期都在计费、期末仍在、且不属于任何 resolved / regressed / new finding 的资源。
2. **对照组按用量类型类别分层。** 实测：全体对照的 g 是 1.028（被 NAT 拉高），而 EBS 层 g 是 1.000。不分层会把卷的节省凭空多算 2.8%。某层没有对照资源才退回全体，并在自检清单里标出。
3. **标准月 30 天。** 测试世界所有成本行是月价 / 30。billed 型预测被 agent 外推到 N 期天数（`analyze.py`：cost * days / res_days），先乘 30 / N 期天数再比较。list_price 型本来就是 30 天。真实账号应换 730 小时。
4. **日均成本，不是发票成本。** 中途创建的资源（restore-scratch 卷 10-08 创建，10 月只计费 24/31 天）用有账单的天数算日均；期中删除的资源，稳态取期末是否仍在计费。
5. **同时算 Unblended 与 Amortized。** 摊销口径节省大于账单口径时标「承诺吸收」：被 Savings Plan 覆盖的实例停机，账单不动，节省进了未用承诺。
6. **保持测量。** 同一条 finding 在 N+2 期再测一次。gp2 改 gp3 在 10 月兑现，11 月被 terraform 回退，必须显示「兑现后丢失」。
7. **账单分解精确闭合。** 逐资源键的恒等式 c1 - c0 = (c1 - cf) + (cf - c0)，cf - c0 = (rate0 x d1 - c0) + rate0 x (g - 1) x d1，加总成七项：已核实节省、回归损失、新增浪费、日历天数、用量漂移、其他移除、其他新增。全程 Fraction 运算，等式精确成立，不是舍入后相等。
8. **独立复算。** 用世界价格表（单价 x 规格）重算被处理资源的标准月成本，与 Cost Explorer 汇总比对。

## 范围之外

场景里没有中途删除、没有被承诺覆盖的 resolved 项；这两个检测只由合成单元测试覆盖。给场景加这类样例需要改 testenv，不属于本 change，记入证据的 NEXT。
