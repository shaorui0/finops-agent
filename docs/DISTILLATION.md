# 规则层的来源与取舍

本仓库的 `rules/` 从维护者的个人 context 仓库（下称母版）蒸馏而来。母版是私有的，覆盖工作、生活、学习等所有领域；这里只保留和本项目相关、可以公开的部分，并改写成 FinOps 语境。

## 映射

| 本仓库 | 母版 | 怎么处理 |
|---|---|---|
| `rules/SOUL.md` | `SOUL.md` | 保留核心真理（有用不表演、有观点、先查再问、内部大胆外部谨慎），身份改为本项目的 FinOps agent；加上只读、不写入第三方数据、节省金额口径三条边界 |
| `rules/USER.md` | `USER.md` | 只保留职业角色和工作偏好（少即是多、做完=能打开的东西、按阶段推进、可回滚的事直接做、逻辑链要有证据） |
| `rules/COMMUNICATION.md` | `COMMUNICATION.md` + 输出格式契约 | 保留语言风格与 agent 交互原则；加上成本报告的口径规则和博客笔记规则 |
| `rules/WORKSPACE.md` | `WORKSPACE.md` | 结构照搬（路由表 + 命名规则），内容换成本仓库的目录 |
| `rules/axioms/` | 母版的 axioms 目录（50 条） | 选 11 条与"可信的 agent + 成本治理"直接相关的，改写并加「本仓库怎么落地」；另加 2 条项目原生公理 |
| `rules/skills/INDEX.md` | 母版的 skills 索引 | 只索引本仓库的 skill |

## 刻意不带进来的

| 内容 | 原因 |
|---|---|
| 个人背景、人生哲学、职业规划、财务与生活信息 | 私人信息，与本项目无关 |
| 雇主名、内部系统名、工作数据、账号与路径 | 公开仓库，且本项目不使用任何工作数据 |
| 母版的记忆系统、定时任务、私有工具路径 | 依赖母版的目录结构，在这里不成立 |
| 其余 39 条公理（职业、教育、管理哲学等） | 与本项目的判断无直接关系；需要时按同样格式补进来 |

## 公开安全

`tools/check_rules.py` 扫描整个仓库：公开的模式（12 位账号、access key、本地 home 路径）写在代码里；私有的模式（雇主名等）写在被 gitignore 的 `.leak_patterns.local` 里，这样仓库本身不包含它要防的那些词。

## 以后怎么同步

D5 的 cron 定期对比母版与本仓库：母版新增或修改的公理，如果和本项目相关，生成一个 OpenSpec change 提议同步，由维护者决定是否合入。本仓库原生的公理（FA12、FA13 这类）也可以反向提议回母版。
